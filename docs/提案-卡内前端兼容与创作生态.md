# 提案 · 卡内前端兼容与社区创作生态

## 动机（真实数据，非估计）

对 `E:\学习资料` 114 张真实 ST 角色卡只读普查（脚本只读扫描，未执行任何卡内代码）：

| 机制 | 占比 | 信任级别 |
|---|---|---|
| 角色内嵌正则脚本 `extensions.regex_scripts` | 108/114（95%） | 声明式数据 |
| 世界书条目 ST 扩展（position/depth/probability/selective） | 112/114（98%） | 声明式数据 |
| 状态栏占位块（`<StatusBlock>` 等） | 93/114（82%） | 靠正则管线点亮 |
| Tavern Helper 载荷 `tavern_helper` | 97/114（85%） | 代码，需沙箱 |
| MVU `stat_data` 变量系统 | 86/114（75%） | 声明式数据+更新协议 |
| EJS 模板 | 39/114（34%） | 全量=任意 JS，需受限子集 |
| 内联 `<script>` | 9/114（8%） | 代码，需沙箱 |
| 远程加载器（raw.githubusercontent.com） | 1/114 | 远程代码，默认拒绝 |

当前导入器把 `data.extensions` 与 `character_book.entries[].extensions` 整体丢弃
（`src/core/importers/st-card-importer.ts:22-34`），即上述全部机制今天都未进库。

## 已确认决定（驾驶员 2026-09-19 拍板）

1. **兼容路线：无代码兼容先行**（正则管线 → 变量层 → 沙箱 TH shim 后置）。
2. **创作面：声明式组件为主 + 沙箱 JS 作高阶逃生舱**。
3. **皮肤中心：本地包注册表先行**，社区 Git 索引后置。

## 架构：按信任级别四层（对齐总设计案 L1-L4 与 T4 红线）

- **L-A 无代码兼容层（零授权零风险）**
  - 正则渲染管线：ST 正则语义 clean-room 实现（findRegex/replaceString/trimStrings/
    placement/minDepth/maxDepth/runOnEdit/substituteRegex/disabled）；prompt 侧剥离
    状态栏块（保护缓存前缀哈希），显示侧在 `App.tsx:435` sanitize 前做 HTML 变换，
    扩展 DOMPurify profile 允许 div/table/style 作用域 CSS。
  - 世界书条目扩展语义：position/depth/probability/selective/exclude_recursion 映射
    到双模检索器与组装块管线。
  - MVU stat_data 投影：解析为命名空间化 StateOp 锚定楼层 ID，挂事件溯源
    StateManager（不做第二状态源）；每楼更新提取复用管家 prompt+parse 降级档。
  - EJS-lite：仅属性访问/三元/格式化子集；解析失败显示诊断态。
- **L-B 原生创作面（声明式）**
  - 组件清单四表面（状态栏/面板/抽屉/弹窗）JSON spec + 变量绑定；
  - 变量 schema 声明复用 `src/core/types/schema.ts` zod 体系；
  - 皮肤 = design tokens（CSS variables + 资产包）。
- **L-C 沙箱执行层（显式授权）**
  - iframe `sandbox="allow-scripts"` 无同源 + postMessage ABI（L2 版本化）；
  - Tavern Helper shim 表面由 97 卡载荷静态调用普查决定（clean-room：从自有
    fixture 推导，不读 TH/ST 源码）；远程导入默认拒绝。
- **L-D 分发层**
  - 包格式：组件包/皮肤包/变量 schema 包，哈希钉住；本地注册表 manifest；
  - 社区 Git 索引后置。

## P0 前置缺陷（对抗式审查确证，详见 `docs/对抗式审查报告-2026-09-19.md`，实施前必须处理）

**数据完整性（最优先，均为静默数据丢失）**：
- CRITICAL：快照 checkpoint seq 竞态——并发 append 事件永久跳过（`event-log.ts:99-113` + `card-store.ts:103-117`）。
- HIGH：双实例无互斥，端口顺延后第二实例误杀活 run 并双写事件日志产生重复 seq（`bootstrap.ts:78-84`）。
- HIGH：readFrom seq 预检被 payload 内嵌 seq 键绕过（`event-log.ts:148-157`）。

**引擎接线（First Playable 成真的最小集）**：
- HIGH：组装/管家/世界书/降级/一致性协议零接线——POST /api/runs 裸透传 prompt（`run-manager.ts:144`）。
- HIGH：生产前端为硬编码静态原型，UI 与后端零接线、服务器不托管 dist-ui（`App.tsx:10-75`）；SSE 客户端收不到命名事件。
- HIGH：状态/摘要"物理遗忘"未实现——回退后被遗忘楼层的状态与摘要仍进投影与组装（`card-store.ts:679-690`）；回退按全局 floorIndex 跨分支删数据（`:389-394`）。

**声明对账**：
- HIGH："缓存命中率 ≥90%"为硬编码同义反复（`performance-budget.test.ts:133-138`）；阶段 5"真实卡真实模型"门禁未满足（全 mock、pi-ai 零 import、无 golden transcript）——验收报告状态应回退 pending。
- HIGH：OS keychain 是死代码，主密钥明文落盘（`key-store.ts`）；zod 位于 devDependencies 但运行时 import，生产安装即崩。

完整清单（约 40 条）与"经受住攻击的声明"见审查报告。P0 验收标准相应收紧：
真实会话由 Core 驱动、UI 消费真实 API、`pnpm install --prod` 可启动、阶段 5 报告状态对账。

## 合规与红线

- clean-room：正则/TH 载荷/MVU 结构全部从自有卡 fixture 推导，不读 ST/TH 源码，
  与既有红线一致。
- T4 红线维持：沙箱（P5）落地前不执行卡内 JS；L-A/L-B 全程不执行卡内代码。
