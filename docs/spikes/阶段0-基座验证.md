## 二、Spike 0.2：端点能力探测与四级降级阶梯验证

### 1. 验证目标
AIRP 后台管家与世界书双模设计依赖端点真实能力。若端点不支持 Function/Tool Calling，需平滑降级至 JSON mode 或 Prompt+Regex 抽取；若均不支持则显式禁用，绝不静默失败。
探测逻辑：
- **Tier 1 (Tool Calling)**：携带 `tools` 与 `toolChoice: "required"` 发起探测，若成功返回 `tool_calls` 则定级为 1；
- **Tier 2 (JSON Mode)**：经 `onPayload` 注入 `response_format: { type: "json_object" }`，若输出合法 JSON 则定级为 2；
- **Tier 3 (Prompt+Parse)**：普通文本提示，模型输出 markdown 代码块 ` ```json ... ``` ` 并成功解析，定级为 3；
- **Tier 4 (Disabled)**：均不支持则显式关闭管家结构化提取并上报。

### 2. 执行命令与输出摘录
执行命令：
```bash
node spikes/pi-ai-standalone/probe.mjs
```

实测输出：
```

PASS  探测定级 mode=tools  got tier=1 (tool-calling), expect=1
REQ /v1/json/chat/completions tools=true rf=false
REQ /v1/json/chat/completions tools=false rf=true
PASS  探测定级 mode=json  got tier=2 (json-mode), expect=2
REQ /v1/text/chat/completions tools=true rf=false
REQ /v1/text/chat/completions tools=false rf=true
REQ /v1/text/chat/completions tools=false rf=false
PASS  探测定级 mode=text  got tier=3 (prompt+parse), expect=3

== 结论: 探测阶梯逻辑全部通过 (3 项) ==
```

### 3. 结论与关键事实
- 四级降级探测算法在基于 `pi-ai` 的 ModelPort 包装下逻辑完全闭环；
- 无论端点是原生支持 Function Call（如 OpenAI / DeepSeek / Claude），或是仅支持 JSON Mode（如部分开源微调模型），亦或是纯文本老旧端点，探测器均可在 1~3 次轻量探测请求内精确定位端点等级并保存于端点 Profile 中。
