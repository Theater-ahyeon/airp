## 二、CRITICAL（1 条）

**C-1 快照 checkpoint seq 竞态：并发 append 事件被永久静默跳过**
`event-log.ts:99-113`（快照触发在 append 互斥锁释放后）+ `card-store.ts:103-117`（checkpoint.seq = replayRes.lastSeq，而 replay 内部先 readFrom 后 lastSeq，两步之间落地的 append 更新 lastSeq 却不在树里）。已复现：快照 seq=2001 但树只吸收到 1999，之后 replay 从 2002 起，seq 2001 的事件**永久丢失**，无任何报错。默认快照间隔 50，日志越大窗口越宽。

## 三、HIGH（10 条）

**H-1 状态"物理遗忘"未实现**：`card-store.ts:679-690` 重放无条件 applyStateOp/setSummary；`state-manager.ts` 的 projectState(activeFloorIds) 全仓零生产调用点。已复现：rollback 到第 1 楼后 `state.secretRevealed=true` 与覆盖 f3-f4 的摘要仍出现在投影里。阶段 3 报告"物理遗忘测试通过"是手造 activeFloorIds fixture，未经过真实回退路径。

**H-2 回退按全局 floorIndex 跨分支物理删除其它分支楼层**：`card-store.ts:389-394` 收集遗忘楼层无 branchId 过滤。已复现：main 分支回退把 b2 分支整链删光。分支语义与回退语义互不相容（core 的 `floor-tree.ts:162-168` 同病）。

**H-3 摘要未来剧情泄漏**：rollback 从不失效 summary；SummaryManager（分支感知、含 forgetBranch）零生产调用点。被遗忘的"未来"经 rollingSummary 重新进入每次组装。

**H-4 组装/管家/降级/一致性协议零接线**：`run-manager.ts:144` 直接发送裸 `[{role:"user",content:prompt}]`——无角色卡、无世界书、无状态、无摘要、无管家等待。waitForFloorSettlement 全仓零调用；能力探测不存在；但ler 静默 catch（违反"绝不静默"）；无 tool calling 的端点被永久钉死 Tier1 且零提取。POST /api/runs 是裸透传。

**H-5 双实例无互斥**：端口 EADDRINUSE 顺延使第二实例绑定新端口打开同一 AIRP_HOME：recoverOnBoot 误杀第一实例活 run（改标 interrupted 并写 run_failed）+ 双写 events.jsonl 产生重复 seq。已复现（run_failed#seq7 与 run_delta#seq7 共享 seq）。触发：连续运行两次 airp。

**H-6 readFrom seq 预检可被绕过**：`event-log.ts:148-157` 用行内第一个 `"seq":` 正则匹配，payload 内嵌 seq 键先被命中 → 事件静默跳过。已复现：`payload.junk={"seq":1}` 使 readFrom(2) 丢 seq4。importCard 原样落盘外部事件即触发面。O(n²) 全量 readFile 债务仍在。

**H-7 "缓存命中率 ≥90%" 是同义反复**：`performance-budget.test.ts:133-138` 字面常量 940/1000，断言永真；全仓无任何命中率测量实现（设计文档明确该指标应来自 usage.cacheRead）；UI 的 94.8%（`App.tsx:17`）也是硬编码。README/NEXT/阶段 5 报告据此宣称达标，证据强度为零。

**H-8 阶段 5 "真实卡真实模型" 门禁未满足**：first-playable-e2e 的"真实卡"是 9 字段手写内联 JSON；MockModelAdapter/MockModelPort 构造后从未调用（死代码）；全部楼层 appendFloor 硬写入；memory-recall-eval 的"模型"是返回预设事实的闭包。pi-ai 在 src/dist/tests/scripts 零 import（唯一出现是注释）。仓库无 golden transcript。总设计案验收账本自标"真实宿主 pending"与阶段 5 报告"全部达成 Passed"直接矛盾。

**H-9 生产前端是硬编码静态原型**：`App.tsx:10-75` INITIAL_SESSION 常量（楼层/成本/摘要全假）；handleSend 本地编造回复；handleUndoRollback = setSession(INITIAL_SESSION)；UI 零 fetch/EventSource（sse-client 仅被单测导入）；服务器无静态文件服务，dist-ui 构建产物无任何消费者。"本地服务器托管前端"与"流式恢复 UI"集成不存在——First Playable 无法通过 UI 玩到。

**H-10 OS keychain 是死代码，主密钥明文落盘**：`key-store.ts` probeOsKeychain 结果被丢弃，无条件返回加密文件方案；32 字节 master key 明文写 `~/.airp/.airp-key`，与密文同目录。Windows 直接短路无 DPAPI。AES-256-GCM 用法本身正确，但密钥管理使"key 不明文落盘"安全效果等同明文（同用户任意进程 5 行代码离线解密）。

## 四、MEDIUM（择要 16 条）

- **M-1 repairTail 首坏行截断**：删掉其后全部合法事件（复现：[ev1,ev2,garbage,ev3] → 只剩 2 条）。
- **M-2 端口回退后 allowedOrigins 钉死原端口**：合法同源 POST 被 403（复现）。NEXT.md"端口回退陷阱已消除"被推翻；bootstrap 二次绑定只修一层且不校验重绑结果。
- **M-3 SSE 连接存在时 server.close() 永久挂起**：优雅退出失效（复现 4s+）。
- **M-4 importCard 裸 fs.writeFile 直写 events.jsonl**：唯一绕过原子写的落盘点；导入中断=截断日志无报错。
- **M-5 appendFloor 读改写不持锁**：并发追加产生重复 floorIndex（复现 [1,2,2]）；swipe/edit/rollback 同构。
- **M-6 SSE 客户端收不到任何服务端事件**：服务端帧带 `event:` 命名事件不触发 onmessage；客户端只注册 onmessage。UI 流式恢复即使接线也不工作。
- **M-7 全部 XSS 测试只跑可绕过的正则 fallback**：vitest node 环境 DOMPurify 不可用 → resolvePurifier 返回 null → fallback 实测放行 `<svg onload>`、`jav&#x09;ascript:`、`data:text/html`。生产浏览器包 DOMPurify 在，但该路径零测试覆盖。
- **M-8 PNG 提取器只认 tEXt**：zTXt/iTXt 卡抛错；chara 优先于 ccv3 与 ST 相反；越过 IEND 采信数据。
- **M-9 "114 张 100% 解析"证据无效**：test-real-cards.mjs 把解析器异常静默计入"普通插画"桶，构造上无法发现失败；目标目录仅本机存在，空扫描也 exit 0。
- **M-10 Core floor-tree undoRollback 是永不可成功的死代码**（checkpoint 楼层必被物理删除），与 runtime 语义分叉。
- **M-11 Core appendFloor 默认父节点取全局最深楼层**（可属其它分支），branchId 归属错误。
- **M-12 tool_search 世界书条目在"双模开启"时被静默吞掉**：工具检索回路不存在，关键词兜底被关——开启功能反而丢条目；两条检索路径语义互斥。
- **M-13 历史预算打包跳中间楼层**：贪心装箱产出带洞对话、连续同角色消息。
- **M-14 prefixHash 用未截断内容计算**：预算波动时不代表真实前缀（缓存键会错误命中）；当前无生产消费方。
- **M-15 万楼冷启动测试手写单个全量快照、零事件重放**（`:147-148` 直接 cast 调 save）；真实写入路径 O(n²) 实测 9,800 楼 11.5 分钟（每 50 事件全量重放一次），无任何测试覆盖。读路径 60ms 真实成立。
- **M-16 隔离检查检测面窄**：只扫 import 语句；core 实际用 Node Buffer 全局（png-card-extractor）；错误 cwd 下空跑也 PASS（exit 0, "0 core files"）。
- **M-17 zod 在 devDependencies 但运行时 import**：`pnpm install --prod` 后启动即 ERR_MODULE_NOT_FOUND；bin/airp.mjs 源码回退路径 import("../src/runtime/bootstrap.js") 指向不存在的文件（永不可用）。
- **M-18 原版卡浅冻结**：tags 数组在 original/workingCopy 间共享引用，"原版不可变"被侧信道击穿（复现）。
- **M-19 "60fps / 单楼 0.2ms" 零测量**：virtualization-benchmark 计时的是 4 条算术表达式；无任何浏览器 trace 工件；阶段 4"滚动 60fps（trace 证据）"退出门禁从未产出。
- **M-20 ST 导入丢 secondary_keys/name/description**：条目 id 用 Math.random 非确定性。

## 六、结构诊断

代码库呈现"**演示层真实、引擎层空转**"模式：HTTP/SSE/持久化骨架（阶段 2）质量扎实；但阶段 3（状态/管家/组装）与阶段 4（前端）的交付物是**未接线的孤立模块 + fixture-only 测试**，阶段 5 报告在总设计案验收账本仍标 pending 时宣告"全部达成 Passed"。97 用例全绿为真，但绿色来自测试绕过了所有真实路径。
